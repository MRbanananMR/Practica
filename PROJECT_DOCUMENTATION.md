# CHAT — Подробная документация проекта

## 1. Что это за проект

Проект называется CHAT. Это мини-социальная сеть, в которой:

- пользователь может зарегистрироваться;
- войти в аккаунт;
- создать пост;
- увидеть посты всех пользователей в общей ленте;
- переключать интерфейс между русским и английским языком.

По смыслу это упрощённый аналог социальной сети типа Instagram, но без сложных функций и без базы данных на сервере в продакшене.

---

## 2. Какие технологии используются

Проект написан на Python с использованием веб-фреймворка Flask.

### Основные технологии:

- Python — основной язык программирования;
- Flask — веб-фреймворк для создания сервера и маршрутов;
- SQLite — лёгкая база данных для хранения пользователей и постов;
- HTML — страницы сайта;
- CSS — оформление интерфейса;
- Jinja2 — шаблонизатор для HTML;
- unittest — автоматические проверки.

---

## 3. Как устроен проект по файлам

### app.py
Это главный файл проекта. В нём:

## 4. Как работает проект в целом

Когда пользователь открывает сайт, Flask запускает приложение и начинает обрабатывать HTTP-запросы.

Например:

- пользователь заходит на `/`;
- сервер проверяет, авторизован ли он;
- если нет, он отправляет его на страницу логина;
- если да, открывает ленту.

Каждый запрос идёт через маршруты (routes). Маршруты — это адреса типа:

- `/login`
- `/register`
- `/logout`
- `/posts/create`
- `/`

---

## 5. Как работает регистрация

### Порядок действий

1. Пользователь открывает страницу регистрации.
2. Вводит логин и пароль.
3. Данные отправляются на сервер через POST-запрос.
4. Сервер проверяет:
   - заполнены ли оба поля;
   - существует ли такой пользователь уже.
5. Если всё норм, пароль хешируется.
6. Данные сохраняются в таблицу `users` в SQLite.
7. Пользователь автоматически входит в систему.

### Важный момент

Пароль нельзя хранить в открытом виде. Поэтому используется функция `generate_password_hash()`, которая превращает пароль в безопасный хеш.

При входе в систему пароль проверяется через `check_password_hash()`. Это важно для безопасности.

---

## 6. Как работает логин

Процесс входа:

1. Пользователь вводит логин и пароль.
2. Данные отправляются на сервер.
3. Сервер находит пользователя по логину.
4. Проверяет, совпадает ли пароль.
5. Если совпадает, в сессию записывается `user_id`.
6. Пользователь переходит на главную ленту.

### Что такое сессия

Сессия — это механизм, который сохраняет информацию о пользователе между запросами.

Например:

```python
session["user_id"] = user["id"]
```

Это значит: "запомни, что пользователь с таким id вошёл в систему".

Во всех последующих запросах Flask понимает, кто именно сейчас авторизован.

---

## 7. Как работает лента постов

После входа сервер открывает маршрут `/`.

В этот момент выполняется код:

1. Проверяется, есть ли `user_id` в сессии.
2. Если нет — редирект на страницу логина.
3. Если есть — берётся текущий пользователь.
4. Запрашиваются все посты из базы данных.
5. Посты сортируются по времени — от новых к старым.
6. Результат передаётся в шаблон `feed.html`.

### SQL-запрос на ленту выглядит так:

```sql
SELECT posts.id, posts.content, posts.created_at, users.username
FROM posts
JOIN users ON users.id = posts.user_id
ORDER BY posts.created_at DESC
```

Это значит:

- взять посты;
- привязать каждого пост к автору;
- получить имя автора;
- отсортировать по времени.

---

## 8. Как работает создание поста

Когда пользователь пишет текст и нажимает кнопку, выполняется маршрут `/posts/create`.

### Внутри функции `create_post()`:

1. Проверяется, авторизован ли пользователь.
2. Берётся значение из формы `content`.
3. Убираются лишние пробелы.
4. Если текст пустой — выводится ошибка.
5. Если текст есть — он сохраняется в таблицу `posts`.
6. После этого пользователь возвращается на главную страницу.

### SQL-добавление выглядит так:

```python
INSERT INTO posts (user_id, content) VALUES (?, ?)
```

То есть в таблицу `posts` сохраняются:

- id автора;
- текст поста;
- дата создания.

---

## 9. Как устроена база данных

В проекте используется SQLite, и база хранится в файле `instance/social.db`.

### Таблица `users`
В ней хранятся пользователи:

- `id` — уникальный идентификатор;
- `username` — логин пользователя;
- `password_hash` — зашифрованный пароль.

### Таблица `posts`
В ней хранятся записи пользователей:

- `id` — идентификатор поста;
- `user_id` — кто автор поста;
- `content` — текст поста;
- `created_at` — когда пост опубликован.

Связь между таблицами такая:

- у каждого поста есть `user_id`;
- этот id связан с соответствующим пользователем в таблице `users`.

## 10. Как устроена локализация

Локализация — это перевод интерфейса на разные языки.

В проекте есть словарь переводов:

```python
TRANSLATIONS = {
    "ru": {...},
    "en": {...}
}
```

### Что это значит

Для каждого языка есть отдельный словарь:

- русский (`ru`)
- английский (`en`)

Внутри словаря хранятся пары:

```python
"login": "Войти"
```

или

```python
"login": "Log in"
```

### Как выбирается язык

Функция `get_locale()` смотрит в сессию:

```python
return session.get("lang", "ru") if "lang" in session else "ru"
```

Если пользователь выбрал язык, он сохраняется в `session["lang"]`.

### Как переводится текст

Функция `t(key)` получает ключ текста и возвращает перевод на текущем языке.

Например:

```python
flash(t("logged_in"))
```

Если на русском — в сессию вернётся:

```python
"Вы вошли в систему."
```

Если на английском —

```python
"You have logged in."
```

### Как пользователь меняет язык

В шаблоне есть ссылки:

- `RU`
- `EN`

При нажатии они вызывают маршрут `/set_language/<lang>`.

Код:

```python
@app.route("/set_language/<lang>")
def set_language(lang):
    if lang in TRANSLATIONS:
        session["lang"] = lang
    else:
        session["lang"] = "ru"
    return redirect(request.referrer or url_for("index"))
```

То есть:

1. пользователь нажимает RU или EN;
2. язык сохраняется в сессию;
3. все следующие тексты подставляются на этом языке.

## 11. Как работает Jinja2 в шаблонах

Файлы HTML в папке `templates` не просто статические страницы. Они используют шаблонный язык Jinja2.

Например:

```html
<h1>{{ t('login') }}</h1>
```

Это значит:

- вызови функцию `t('login')`;
- подставь результат в HTML;
- на экране будет нужный текст.

Также используется условие:

```html
{% if session.get('user_id') %}
```

Это значит: если пользователь вошёл в систему, показываем одну часть страницы, иначе — другую.

## 12. Как работает маршрутизация в Flask

Функции вида:

```python
@app.route("/login", methods=["GET", "POST"])
```

связывают URL-адрес с функцией обработки.

То есть:

- если человек открывает `/login`, Flask вызывает функцию `login()`;
- если человек отправляет форму на `/register`, вызывается функция `register()`;
- если человек нажимает кнопку публикации поста, вызывается функция `create_post()`.

## 13. Как работает процесс “пользователь → сервер → база данных → страница”

### Пример: пользователь регистрируется

1. Пользователь вводит логин и пароль в форму.
2. Форма отправляет POST-запрос на `/register`.
3. Flask получает данные.
4. Сервер проверяет их.
5. Если всё корректно, создаёт запись в базе данных.
6. Сохраняет `user_id` в сессию.
7. Перенаправляет на главную страницу.
8. На главной странице сервер извлекает посты и пользователя.
9. HTML-шаблон отображает ленту.
