# CHAT

CHAT - учебное веб-приложение социальной ленты. Пользователь может создать аккаунт, войти в систему, опубликовать текстовый пост и просматривать публикации остальных пользователей.

README описывает текущую реализацию и порядок запуска проекта на локальном компьютере.

## Возможности

- регистрация по имени пользователя и паролю;
- вход и выход из аккаунта;
- создание текстовых публикаций;
- общая лента, отсортированная от новых публикаций к старым;
- русский и английский языки интерфейса;
- хранение аккаунтов и публикаций в SQLite;
- автоматические проверки основных сценариев.

## Технологии

- Python 3;
- Flask для обработки HTTP-запросов и формирования страниц;
- SQLite для хранения пользователей и публикаций;
- HTML и Jinja2 для шаблонов страниц;
- CSS для оформления;
- `unittest` для тестирования.

## Требования

- Python 3.10 или новее;
- `pip` для установки зависимостей.

Проверить версию Python можно командой:

```powershell
python --version
```

В Windows также можно использовать команду `py --version`.

## Установка и запуск

Откройте терминал в корневом каталоге проекта и выполните команды.

### 1. Создать виртуальное окружение

Виртуальное окружение изолирует библиотеки этого проекта от остальных Python-проектов на компьютере.

```powershell
py -m venv .venv
```

### 2. Активировать окружение

В Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Если PowerShell запретит выполнение скрипта активации, можно не менять системную политику, а запускать Python и pip напрямую из `.venv\Scripts`.

### 3. Установить Flask

```powershell
python -m pip install Flask
```

### 4. Запустить приложение

```powershell
python app.py
```

После запуска откройте в браузере адрес:

```text
http://127.0.0.1:5000
```

Чтобы остановить сервер, вернитесь в терминал и нажмите `Ctrl+C`.

## Основные сценарии

### Регистрация

1. Откройте страницу регистрации.
2. Укажите имя пользователя и пароль.
3. Приложение проверит, что поля заполнены, а имя ещё не занято.
4. Пароль будет сохранён в виде хеша, а не обычного текста.
5. После успешной регистрации приложение создаст сессию пользователя и откроет ленту.

### Вход и выход

При входе приложение ищет пользователя по имени и сверяет введённый пароль с сохранённым хешем. Успешный вход записывает идентификатор пользователя в сессию. Выход удаляет этот идентификатор из сессии.

### Публикация

Авторизованный пользователь вводит текст и отправляет форму. Приложение проверяет, что текст не пустой, сохраняет его вместе с идентификатором автора и возвращает пользователя в ленту.

### Общая лента

При открытии главной страницы приложение получает публикации из SQLite и связывает каждую запись с именем автора. Лента показывает новые записи первыми. Пользователи приложения, работающие с одной и той же базой данных, видят общие публикации.

## Локализация

Поддерживаются русский (`ru`) и английский (`en`) языки. Переводы интерфейса собраны в словаре `TRANSLATIONS` в файле `app.py`. Выбранный язык хранится в сессии браузера. В HTML-шаблонах переведённые строки запрашиваются через функцию `t()`, например `t('login')`.

Для добавления нового текста нужно добавить одинаковый ключ в словари обоих языков, а затем использовать этот ключ в шаблоне или серверном сообщении.

## Хранение данных

Приложение использует SQLite. При локальном запуске файл базы находится в `instance/social.db`.

В базе предусмотрены две таблицы:

- `users`: идентификатор, имя пользователя и хеш пароля;
- `posts`: идентификатор публикации, идентификатор автора, текст и время создания.

SQLite-файл является локальным: он доступен процессу приложения на этом компьютере. Чтобы разные компьютеры могли пользоваться одним общим сайтом и общей базой, приложение нужно развернуть на сервере и подключить к подходящему серверному хранилищу. Один только GitHub-репозиторий не запускает Flask-сайт и не делает локальную базу общедоступной.

## Тестирование

Из корневого каталога проекта запустите:

```powershell
python -m unittest discover -s tests -v
```

Тесты используют временную базу данных, поэтому не должны менять локальные пользовательские данные в `instance/social.db`.

## Git и ветки

`main` содержит основную версию проекта. Для отдельной задачи можно создать рабочую ветку, внести в неё связанные изменения, проверить тесты и затем объединить её с `main`.

Пример рабочего цикла:

```bash
git switch -c feature/profile
git add .
git commit -m "Add user profile page"
git switch main
git merge feature/profile
git push origin main
```

Коммиты стоит делать небольшими и называть по сути изменений. Например: `Add registration form` или `Translate feed page`. Не добавляйте в Git виртуальное окружение, секреты и локальную базу с личными данными.

## Ограничения текущей версии

- публикации содержат только текст;
- нет редактирования и удаления публикаций;
- нет восстановления пароля, подтверждения почты и ограничения частоты запросов;
- SQLite предназначена для учебного и небольшого локального использования;
- встроенный режим запуска Flask предназначен для разработки, а не для публичного производственного сервера;
- значение `SECRET_KEY` в учебной конфигурации необходимо заменить на секрет из переменной окружения перед развёртыванием в интернете.
